<context>
The V1 generate.md prompt (validated 18/18 with GPT-4.1 nano on hard
budgets) trains the model to honor a single token budget per call.
V2 changes generation in three ways:

1. **Soft budgets.** Hard-capping `max_tokens` at 8/16/24/32 forces
   mid-thought truncation (trailing commas, "trunc" mid-word). V2

   asks the model to "respond with JSON" — the schema does.

strings, non-imperative starts) — Mission 4 implements that. This
mission only revises the prompt. It does NOT change pipeline code.

### Section 4 body (write this exactly)

```
## Soft Budget + Three-Draft Discipline

The caller provides a target token count `n` (typically in the range
8–32). It is a CONCISION TARGET, not a ceiling — write as if `n` is
the budget, but the API will accept up to ~64 tokens. Stop at the
natural sentence boundary, not at the budget line. A description that
ends mid-thought is a bug, not a feature.

You return THREE drafts in a single response, in increasing refinement:

- `draft_1` — broad first attempt. The full thought, concrete nouns,
  imperative verb, no hedging. Aim for `n + 4` tokens or fewer.
  Allowed to be slightly verbose.
- `draft_2` — tighter rewrite. Same meaning, fewer tokens. Aim for
  `n` tokens or fewer. Drop any word whose removal does not change
  meaning.
- `draft_3` — final form. Sharpest expression. Aim for `n - 2`
  tokens or fewer if achievable without losing meaning. If `draft_2`
  is already optimal, return it again — duplication is honest.

The MLD pipeline embeds all three drafts and runs convergence within
and across tiers. The best shortest, best medium, and best long get
handed to a validation gate. Your job is to produce three honest
attempts at increasing refinement — not three randomly-varied
sentences at the same length.
```

- Build the user content for the generation call as
  `f"target_n={target_n}\n\n{input_text}"` so the model sees the
  concision target. The prompt itself instructs the model to honor
  it.
- Issue `n_calls` parallel generation calls via
  `api.generate(prompt=prompt, content=..., model=generation_model,
   temperature=temperature, max_tokens=max_tokens_ceiling,
   schema=_THREE_DRAFT_SCHEMA, n=1)`.
- Collect 3*n_calls candidates: each call produces draft_1, draft_2,
  draft_3. Tag each candidate with its draft tier ("d1", "d2", "d3")
  and originating call index. Skip any call that failed to return
  structured output (count it under candidates_filtered).

##### Phase 2 — Pre-filter

- Run `_pre_filter` over the candidate strings. Keep `(text, tier,
  call_idx)` triples for passing candidates.

##### Phase 3 — Degenerate pre-check (textual)

- If >50% of passing candidate STRINGS are byte-equal to one another
  (count duplicates by `Counter(passing_texts).most_common(1)`):
  - Re-issue `n_calls` once more (single re-roll) and merge.
  - Set `MLDResult.deduped = True`.
- Keep the candidate list as a list of triples; do NOT collapse
  duplicates before embedding (they contribute to centroid mass
  honestly).

##### Phase 4 — Embed

- Single batch call to `api.embed_text(passing_texts,
  dim=embed_dim, model=embed_model)`. The embed_text helper exists
  in `tools.utils.api`.

##### Phase 5 — Degenerate pre-check (geometric)

- Compute pairwise cosine similarity on the cloud (numpy).
- If `avg_offdiag_cosine_sim > 0.999`:
  - Set `MLDResult.degenerate_pre_check = True`.
  - Skip antipode test; jump to Phase 7 (gate) on the centroid-nearest
    candidate alone.

##### Phase 6 — Antipode convergence

- Compute centroid of the full cloud.
- Find centroid-nearest candidate `P`.
- Compute antipode `2*centroid - P`.
- Find the antipode's nearest neighbor in the cloud.
- `converged = neighbor_idx != nearest_idx`.
- Pick up to 4 alternatives by varying axes (median word-length,
  shortest-above-target_n/2, highest mean cosine to neighbors,
  closest-to-centroid from a different draft tier than P).
- If not converged, the gate still runs on the centroid-nearest +
  alternatives — non-convergence is a confidence signal, not a
  pipeline halt.

##### Phase 7 — Gate

- Build gate content: JSON object
  `{"function_or_text": input_text, "candidate": <text>}`.
- Call `api.generate(prompt=_GATE_PROMPT, content=..., model=gate_model,
  temperature=0.0, max_tokens=128, schema=_GATE_SCHEMA, n=1)` for the
  centroid-nearest candidate.
- If gate returns `valid=True`: gate_verdict = "valid", description =
  centroid-nearest. Skip Phase 8.
- If gate returns `valid=False` AND there is exactly one alternative
  better-shaped (e.g., shortest-above-target_n/2 in a different draft
  tier), retry the gate on that alternative. If it passes, accept.
- Otherwise: gate_verdict = "ambiguous". Continue to Phase 8.

##### Phase 8 — Selection (Opus)

- Build selection content: JSON object with `function_or_text`,
  `candidates: [{index, text, tier, dist_to_centroid, length}, ...]`
  for the centroid-nearest plus up to 4 alternatives.
- Call `api.generate(prompt=_SELECT_PROMPT, content=...,
  model=selection_model, temperature=0.0, max_tokens=256,
  schema=_SELECT_SCHEMA, n=1)`.
- description = candidate at `selected_index`.
- selection_rationale = the structured `rationale` string.

##### Phase 9 — Confidence

- Base = 1.0 if converged, 0.5 otherwise.
- Subtract 0.1 if degenerate_pre_check fired.
- Subtract 0.1 if deduped fired.
- Subtract 0.2 if gate_verdict == "ambiguous".
- Clamp [0.0, 1.0].

#### Backwards-compat surface

`tools/utils/mld.py` is NOT modified. The new pipeline lives at
`tools/mld/pipeline.py`. Callers update their imports as part of
later missions.

    - If expected_pre_hash is not None and current file_hash != expected_pre_hash,
      raise RuntimeError("pre-hash mismatch") without touching the file.
    - If expected_pre_hash is None, this is a new-file write; the file must

    - skip_git=True suppresses the two-commit bracket — used during sprint

    agent: str,
    reason: str,
    skip_git: bool = False,
) -> CrisprResult:
    """Replace lines [line_start, line_end] with replacement.

    Same gates as crispr_write. expected_pre_hash is REQUIRED — line-range
    edits make no sense on a file you have not first read.
    """

#### Git bracket implementation

```python
def _git_commit(message: str) -> str:
    """Run `git -C /project add -A && git -C /project commit --allow-empty -m <message>`,
    return short ref. If git is unavailable or pre-commit hooks fail, raise.
    """
```

The bracket sequence:
1. Capture current HEAD ref (`git rev-parse --short HEAD`).
2. `_git_commit(f"pre-write: {file} by {agent}: {reason}")` — yields
   pre_commit ref.
3. Perform the write.
4. `_git_commit(f"post-write: {file} by {agent}: {reason}")` — yields
   post_commit ref.

If step 2 or step 4 fails (e.g., dirty unrelated state), the helper
DOES NOT swallow the failure. It raises with the git stderr in the
message. The caller decides how to recover.
