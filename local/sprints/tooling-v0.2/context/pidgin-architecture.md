# Pidgin Architecture

Pidgin is a Python library and CLI for semantic indexing, querying, validation, and precision editing of codebases. It stores all documentation externally (never modifies source by default), exposes a closed vocabulary of LLM interaction verbs, and packages the MLD convergence algorithm as its core compression engine.

## Name and Positioning

Pidgin — a reduced-vocabulary language that emerges when two groups with no common language need to communicate using shared primitives. This is the Cactus Problem: "to communicate across an unbridgeable gap, you do not need shared experience, you need shared primitives."

Tagline: "RISC for LLMs."

The three-layer framing:
- **Origami** — the philosophy. Principles, constraints, the why. Ships as a document.
- **Pidgin** — the tool. Verb vocabulary, MLD pipeline, documentation store, skills. Ships as a package.
- **Marionette** — the executor. Remote MCP server that uses Pidgin internally. Ships as a container.

## Four CLI Verbs

Each is a CLI command, a Python API call, and a Pidgin verb.

**index** — read source, extract functions, generate embeddings, store in nest. Never touches source files. Read-only against the target repo. Produces `.pidgin/nest/` and `.pidgin/CLAUDE.md`.

**update** — surgical edits to existing files. CRISPR operations: line-character precision, source hash verification before and after write, git commit bracketing at the file level. This is the only verb that modifies existing source.

**new** — create complete files from generated content. No hash verification (nothing to verify against). No pre-write commit (no prior state to capture). One git commit after all generated files are written. Used for ORIGAMI.md, ARCHITECTURE.md, CLAUDE.md indexes, behavioral contracts.

**compress** — read input text, MLD-compress it, produce a new artifact. Input is read-only. Output is a new file. Used for principle compression, document summarization, any text→shorter-text transformation.

## Three Permission Flags

Default is read-only. Flags are additive and independent.

- `--write-db` — permission to write to the nest (ChromaDB store). Used by index and compress.
- `--write-source` — permission to modify source files. Used by update. The most privileged mode. Flag name makes the permission explicit.

No flag escalation hierarchy. A tool could theoretically need --write-source without --write-db, or --write-db without --write-source. Permissions are orthogonal.

## Store Convention

The store lives at `.pidgin/nest/` in the target repo root. Contains ChromaDB persistent storage files.

`.pidgin/CLAUDE.md` — auto-generated by `pidgin index`. Teaches agents how to query the store. Not hand-written.

`.pidgin/` can be committed (Roboflow ships pre-indexed repos) or gitignored (customer's internal repo, local artifact). The convention supports both without configuration.

Nested nest discovery: `pidgin init` at a parent repo finds `.pidgin/nest/` in subdirectories, registers them as pointers. A query with namespace `.` searches all nests.

## Pidgin Verb Vocabulary (LLM Interaction)

Pidgin defines a closed set of verbs for talking to models. Each verb has a fixed input schema and a fixed output schema. An agent cannot construct an arbitrary prompt — it calls a verb.

Known verbs (design-time, subject to sprint validation):
- **converge** — the core MLD verb. Takes input (code or description), a direction (code→description or description→code), a target complexity, and produces the minimum convergent output. Replaces the V2 concept of "generate" as a separate operation.
- **gate** — pass/fail/unsure with structured justification. Takes a candidate and evaluation criteria, returns `{valid: bool, reason: string}`.
- **rank** — order N candidates by a stated criterion, return indices with reasons.
- **summarize** — compress input to a target density, return structured output. May internally use converge.
- **classify** — assign input to one of N categories with confidence.
- **extract** — pull structured data from unstructured input.

Each verb call is an XML document: a cached preamble (system prompt, principles, output schema) plus a variable payload. The preamble caches because it's identical per verb per document type. The cost structure falls directly out of this split.

## Document Type System

The nest stores typed documents. Every record has a `doc_type` metadata field:
- `function_description` — MLD-compressed function description
- `module_summary` — recursive summarization of a module
- `repo_overview` — top-level repository description
- `behavioral_contract` — function contract (inputs, outputs, side effects, invariants)
- `module_behavior` — module behavioral spec
- `architecture` — repo-level architecture description

New document types require schema design — they go through the same review as new verbs.

## CLI Shape

```
pidgin index .                          # index current repo
pidgin index ./src --write-db           # index with store writes
pidgin query "what handles retry"       # search the nest
pidgin update ./parser.py --write-source  # surgical edit
pidgin new origami                      # generate new file
pidgin compress manifesto.md            # MLD-compress text
pidgin init                             # discover and register nested nests
```

Invocation: `python -m pidgin` or via shell alias / venv python direct call.
