## Summary

## Decision Points

Resolve before `/run-sprint`:

- **DP-1: Shared prompt location.** generate.md and validate.md are
  shared between /technologic and /digest. Options: (a) `tools/prompts/`
  as shared infrastructure, (b) duplicate into each skill's `prompts/`,
  (c) `.claude/prompts/` shared directory. Default: **(a)**. Skill-specific
  prompts (recomment.md, analyze.md, analyze_anonymized.md) still live in
  `.claude/skills/<name>/prompts/`.
- **DP-2: Convergence embedding dimension.** Design says "tune empirically
  in Phase 2" at 64 / 128 / 256. Default: **keep configurable in
  `utils/mld.py` via `embed_dim` arg; Mission 7 commits a recommended
  default based on discrimination test.**
- **DP-3: Marionette API key availability.** The MLD pipeline calls
  OpenAI (GPT-5 Nano generation, text-embedding-3-small) and Anthropic
  (Haiku validation, Sonnet review, Opus full-corpus). Operator must
  confirm `OPENAI_API_KEY` and `ANTHROPIC_API_KEY` are in
  `local/.env` before Mission 7. Default: **assume yes; Mission 1
  audits and fails HARD if either is missing.**
- **DP-4: Cached prompt padding strategy.** Anthropic's 4,096-token
  floor on Haiku 4.5 / Opus 4.7 means generate.md must be padded to
  qualify for caching. Pad with: (a) Origami principles + Daft Punk
  grammar rules + MLD examples at budgets 8/16/24/32, (b) filler.
  Default: **(a)** — the padding is the prompt.

```
READS: OPENAI_API_KEY and ANTHROPIC_API_KEY from environment (via local/.env)
```

Public surface:

```python
@dataclass
class CostSummary:
    input_tokens: int
    output_tokens: int
    cache_read_tokens: int
    cache_creation_tokens: int
    embedding_tokens: int
    dollars: float
    model_breakdown: dict[str, dict]  # per-model {tokens, dollars, cache_hit_rate}

@dataclass
class GenerateResult:
    text: str | None              # None if structured (see `structured`)
    structured: dict | None        # dict if strict tool use or response_format
    usage: dict                    # {input_tokens, output_tokens, cache_read, cache_creation}
    model: str

async def generate(
    prompt: str,                   # cached prefix (system)
    content: str,                  # variable suffix (user)
    model: str = "claude-haiku-4-5",
    temperature: float = 0.8,
    max_tokens: int = 512,
    schema: dict | None = None,    # JSON Schema for strict tool use / response_format
    cache: bool = True,
    n: int = 1,                    # if > 1, returns list of GenerateResult
) -> GenerateResult | list[GenerateResult]: ...

async def generate_batch(
    prompt: str,
    contents: list[str],
    concurrency: int = 10,
    **generate_kwargs,
) -> list[GenerateResult | list[GenerateResult]]: ...

async def embed_text(
    text: str | list[str],
    dim: int = 1536,
    model: str = "text-embedding-3-small",

def reset_cost_totals() -> None: ...
```

Implementation requirements:

1. Provider routing by model prefix:
   - "claude-*" → Anthropic client.
   - "gpt-*" → OpenAI Chat Completions.
   - "text-embedding-*" → OpenAI Embeddings.

2. Anthropic calls:
   - Pass `prompt` as a single system block with
     `cache_control: {"type": "ephemeral"}` when `cache=True`.
   - If `schema` is provided, define a single strict tool named
     `answer` with that schema, set `strict: True`, set
     `tool_choice: {"type": "tool", "name": "answer"}`. Return the
     tool_use.input dict as `structured`.
   - For `n > 1`, fire `n` parallel requests. First request serialized
     to warm the cache (per Anthropic guidance in
     context/anthropic-prompt-caching.md §9); remaining n-1 dispatched
     concurrently once the first returns.
   - Track cache_read_input_tokens and cache_creation_input_tokens
     from response.usage.

3. OpenAI calls:
   - For chat: use `client.chat.completions.create` with the prompt
     as a system message and content as user.
   - For `schema`: pass `response_format={"type": "json_schema",
     "json_schema": {"name": "answer", "schema": schema, "strict": True}}`.
   - For `n > 1`, set `n=n` on the request (OpenAI supports this
     natively).
   - For embeddings: `client.embeddings.create(model=..., input=...,
     dimensions=dim)`.

4. Prompt caching:
   - OpenAI caches automatically for prompts ≥1024 tokens (Sep 2024).
     No header required. Track cached_tokens from usage.
   - Anthropic requires explicit cache_control on the system block.
   - If cache=False, do not send cache_control.

5. Cost tracking:
   - Maintain a module-level _cost_totals CostSummary (thread-safe via
     asyncio.Lock).
   - After every call, update totals using these base rates
     ($ / million tokens):
       claude-haiku-4-5: input 1.00, output 5.00, cache_read 0.10,
         cache_write_5m 1.25
       claude-sonnet-4-6: input 3.00, output 15.00, cache_read 0.30,
         cache_write_5m 3.75
       claude-opus-4-7: input 5.00, output 25.00, cache_read 0.50,
         cache_write_5m 6.25
       gpt-5-nano: input 0.05, output 0.40, cache_read 0.005
       text-embedding-3-small: input 0.02
     Constants should be defined as a `RATES` dict at module top.

6. Retry with exponential backoff:
   - 3 attempts. Base delay 1s. Retry on rate limit (429) and
     transient server errors (5xx).

7. Concurrency:
   - `generate_batch` uses asyncio.Semaphore(concurrency=10) by default.

8. Load credentials:
   - On module import, try to load /project/local/.env via
     python-dotenv (absolute path resolved from this file's location).

### A. /project/tools/utils/mld.py

Module header:
```
MODULE: mld
DOES: Find the minimum lossless description of an input via consensus-driven compression.
EMITS: MLDResult (description, token_count, confidence, convergence flag, cost)
READS: input text, cached prompt, budget range, candidate count
IMPLEMENTS: generate → grammar filter → embed → antipode convergence → binary search → validate
DEPENDS: utils.api, numpy, asyncio
```

Public surface:

```python
@dataclass
class MLDResult:
    description: str              # the MLD itself (centroid-nearest at minimum budget)
    token_count: int              # minimum convergent budget
    complexity_score: int         # same as token_count — free metric
    confidence: float             # 0..1, convergence speed
    converged: bool               # False = non-convergence signal
    candidates_generated: int
    candidates_filtered: int      # grammar-rejected
    validation_rationale: str     # reasoning-model explanation
    budget_tried: list[int]       # budgets the pipeline explored
    cost: CostSummary             # from api.cost_totals()

async def mld(
    input_text: str,
    prompt: str,
    budget_range: tuple[int, int] = (8, 32),
    budget_step: int = 8,
    n: int = 10,
    temperature: float = 0.8,
    generation_model: str = "gpt-5-nano",
    validation_model: str = "claude-haiku-4-5",
    embed_dim: int = 128,
    schema: dict | None = None,
) -> MLDResult: ...

def grammar_filter(
    candidates: list[str],
    max_tokens: int,
    schema: dict | None = None,
) -> tuple[list[str], list[str]]:
    """Return (passing, rejected). Mechanical, no LLM."""
```

Implementation:

1. Grammar filter rules (from design Decision 6):
   - Starts with an imperative verb (simple check: first token is not
     in a hedging/filler blacklist and is not a copula "is"/"was").
   - Contains no hedging words: may, might, could, possibly, generally,
     typically, arguably, perhaps.
   - Contains no filler: basically, essentially, effectively, simply,
     just, really.
   - Contains no passive-voice markers: " is <verb>ed by ", " was
     <verb>ed by ", " been <verb>ed ".
   - Token count ≤ max_tokens (use len(candidate.split()) as a cheap
     approximation — document this deviation from true tokenization).
   - If schema provided, JSON-validates. Otherwise text is accepted.

2. Generation phase (per budget tier):
   - Call api.generate(prompt=prompt, content=input_text, model=
     generation_model, temperature=temperature, max_tokens=budget,
     n=n). Dispatch all budget tiers IN PARALLEL via asyncio.gather.
   - Each tier produces up to n candidates.

3. Grammar filter: reject non-compliant. If <n/2 pass for a tier,
   rerun the tier once with a fresh set. If still <n/2, mark that
   tier "underfilled" — continue but lower confidence.

4. Embed phase:
   - api.embed_text(all_passing_candidates, dim=embed_dim).
   - Build a numpy array: (num_passing, embed_dim).

5. Antipode convergence test per tier:
   ```
   cloud = numpy array of candidate embeddings for this tier
   centroid = cloud.mean(axis=0)
   distances = np.linalg.norm(cloud - centroid, axis=1)
   nearest_idx = distances.argmin()
   nearest = cloud[nearest_idx]
   antipode = 2 * centroid - nearest
   neighbor_distances = np.linalg.norm(cloud - antipode, axis=1)
   neighbor_idx = neighbor_distances.argmin()
   if neighbor_idx == nearest_idx:
       sparse (insufficient coverage)
   else:
       converged — centroid is interior to the cloud
   ```
   - Return (converged: bool, centroid_nearest: str, alternatives: list[str]).
   - Alternatives: median-length, shortest-above-threshold,
     highest-internal-consistency (mean cosine-sim to neighbors).

6. Budget search:
   - Run all budget tiers in parallel at the start.
   - Converged budgets: pick the minimum.
   - No budget converged: MLDResult(converged=False, ...).
   - Gap in sequence (converged at 8 and 24 but not 16): flag in
     rationale, prefer the smallest.

7. Validation phase:
   - Pass centroid_nearest + up to 4 alternatives to validation_model
     via api.generate with a strict schema:
     ```
     {
       "type": "object",
       "properties": {
         "chosen_index": {"type": "integer"},
         "rationale": {"type": "string"}
       },
       "required": ["chosen_index", "rationale"],
       "additionalProperties": false
     }
     ```
   - The validation prompt (the `prompt` argument passed to api.generate)
     is a separate concern — the caller of mld() supplies it via a
     closure or via api.generate directly. For mld()'s internal
     validation, use a built-in validate prompt string (defined at
     module top) that says: "Evaluate each candidate. Select the best.
     Explain why."

8. Non-convergence handling:
   - Return MLDResult with converged=False, description =
     centroid_nearest of the largest budget tried (best-effort),
     validation_rationale = "NON_CONVERGENT: <reason>". Do NOT raise.

9. Confidence score:
   - 1.0 if converged at the minimum budget (8).
   - Linear decay as the convergent budget increases.
   - 0.0 if non-convergent.

```python
    """AST-based extraction of defs and classes."""

def parse_rust(source: str, module_path: str) -> list[FunctionRecord]:
    """Regex-based extraction of pub fn/struct/enum/trait items."""

def parse_typescript(source: str, module_path: str) -> list[FunctionRecord]:
    """Regex-based extraction of export function/class/const/interface/type."""

def parse_javascript(source: str, module_path: str) -> list[FunctionRecord]:
    """Same as typescript but no interface/type."""

def parse_go(source: str, module_path: str) -> list[FunctionRecord]:
    """Regex-based extraction of func/type with capitalized names."""

def extract_imports(source: str, language: str) -> list[str]:
    """Return list of imported module names. Python uses ast; others regex."""

    """Return {module_path: set_of_imported_modules}. Internal edges only."""
```

Implementation notes:
- For Python: use ast.parse and walk FunctionDef / AsyncFunctionDef /
  ClassDef. Skip _-prefixed names unless they're `__init__`.
- For Rust: match `^pub fn `, `^pub(crate) fn `, `^pub struct `,
  `^pub enum `, `^pub trait ` at column 0.
- For TS/JS: match `^export (function|class|const|interface|type)`.
- For Go: match `^func ` followed by capitalized identifier (or
  `^func (.*) Name` for methods).
- Visibility: "public" unless the name is _-prefixed (Python),
  lowercase (Go), or not `export`ed / `pub`ed.

Comment prefix lookup by file extension (use Path(file).suffix):
```python
_PREFIX = {
    ".py": "# ",
    ".rs": "// ", ".js": "// ", ".ts": "// ",
    ".tsx": "// ", ".jsx": "// ", ".go": "// ",
```

Tag name pattern: `[A-Za-z0-9:_-]+` (supports "fn:embed" colons).

#### section_get(file, tag) -> tuple[str, dict] | None

Read the file. Determine comment prefix from extension. Search for:
- Opening line: `{prefix}<{tag}[^>]*>` (possibly with trailing content on same line)
- Closing line: `{prefix}</{tag}>`

Two formats:
1. **Single-line**: opening and closing on the same line:
   `{prefix}<{tag} ...>content here</{tag}>`
   → content = the text between `>` and `</tag>`, stripped.
2. **Multiline**: opening on one line, content on subsequent lines (with prefix
   stripped from each), closing on its own line.

Parse attributes from the opening tag string using regex `(\w+)="([^"]*)"`.
Return `(content, attrs_dict)` or `None` if the tag is not found.

`content` is the raw content string with the comment prefix stripped from each line.
For multiline, join lines with `\n`. Do not include the opening/closing tag lines.

#### section_put(file, tag, content, model=None) -> bool

1. Read existing file (empty string if file does not exist).
2. Determine comment prefix from extension.
3. Compute `new_hash = hashlib.sha256(content.encode()).hexdigest()[:8]`.
4. Call section_get to find the existing section (if any).
   - If found and `existing_attrs.get("source_hash") == new_hash`: return `False` (skip).
   - If found: parse `version = int(existing_attrs.get("version", "0"))`, new_version = version + 1.
   - If not found: new_version = 1.
5. Build `updated = datetime.now(timezone.utc).strftime("%Y-%m-%dT%H:%M:%SZ")`.
6. Build the opening tag attributes string, in this fixed order:
   `version="{new_version}" updated="{updated}" by="{_GIT_USER}"` then
   `model="{model}"` (only if model is not None) then `source_hash="{new_hash}"`.
7. Assemble the new section lines:
   - If content has no newlines (single-line content):
     `f'{prefix}<{tag} {attrs}>{content}</{tag}>'`
   - Otherwise (multiline):
     ```
     f'{prefix}<{tag} {attrs}>'
     {prefix}{line1}
     {prefix}{line2}
     ...
     f'{prefix}</{tag}>'
     ```
   For multiline: strip each content line of its trailing whitespace; do not
   add the prefix to blank lines (emit just `\n` for blank lines to avoid
   trailing whitespace).

8. Find and replace existing section, or append:
   - If section exists in the file: replace the entire span from the opening
     tag line through the closing tag line (inclusive) with the new section lines.
   - If section does not exist: append `\n\n` + the new section block to the file.
     If the file ends with a newline already, do not double-blank the boundary —
     just ensure there is exactly one blank line between existing content and the
     new section.
9. Write the modified file with encoding="utf-8". Ensure file ends with `\n`.
10. Return `True`.

#### Public exports

`__all__ = ["section_get", "section_put"]`
